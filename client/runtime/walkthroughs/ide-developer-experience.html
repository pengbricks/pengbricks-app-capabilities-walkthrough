Developer workflow in the IDE

Write a transform in VS Code, debug its edge case with Databricks Connect, and run the same tests locally and on serverless before deploying with a bundle.

The short version

  1. Write plain functions.

    clean_records takes a DataFrame and returns a DataFrame. Because it is a plain function, the notebook, the IDE debugger, pytest, and the deployed job all call the same code.

  2. Debug where you already work.

    Open src/explore.py as a workspace notebook, or use VS Code with Databricks Connect and set a breakpoint. Both step into the same function.

  3. A test catches the edge case.

    Move key normalization after the window and test_duplicates_differing_in_case_and_whitespace_collapse fails. Undo it and the suite passes.

  4. One command validates, one deploys.

    databricks bundle validate --strict --target dev, then bundle deploy --target dev. The deployed job runs the same pytest suite on serverless.

  5. The pipeline editor is live-demo only.

    The reference bundle ships a job, not a pipeline, so nothing in the repo feeds the Lakeflow pipeline editor. It is shown in the workspace.

The author, debug, test loop

Day to day, one change goes around four steps. Each step reuses the same function, so a fix found while debugging is already covered by the test that follows.

Which tool does what

Four tools cover the loop. The notebook and the IDE overlap on purpose: pick the one you prefer, because they reach the same code.

One change, edit to deploy

Follow a single edit. A failing test sends you back before anything is deployed, and the deployed job runs the same suite once more on serverless.

Local and serverless compute

Your code stays on your machine. Databricks Connect sends the Spark work to serverless compute and brings results back, so there is no cluster to start or size.

Demo steps

  1. Show the spec. Open use_cases/general.yml. The transforms take column names from it.
  2. Explore in a notebook. Import the package from src/explore.py and step into clean_records with the notebook debugger.
  3. Debug from the IDE. In VS Code, set a breakpoint on the latest = Window line. Databricks Connect runs it on serverless.
  4. Break it, then fix it. Move key normalization after the window. The duplicate-collapse test fails. Undo the change and the suite passes.
  5. Validate and deploy. Run databricks bundle validate --strict --target dev, then databricks bundle deploy --target dev.
  6. Open the job run. unit_tests, transform, and sql_checks show on one run page you can share.
  7. Show the pipeline editor live. Open it in the workspace; the repo has no pipeline to feed it.
